# 절로가 — 디자인 리뷰 & 리프레시 (2026-10)

"15년차 앱 디자이너가 이 앱을 손본다면 어떻게 했을까"를 구현한 기록이다.
목표는 예쁘게가 아니라 **이 앱이 해야 할 세 가지(마음을 고른다 · 사찰을 읽는다 · 걸어본다)가
첫 화면에서 한 번에 읽히게** 만드는 것이었다. 코드·문서에 남긴 판단 근거를 그대로 옮긴다.

## 2. 원칙 (이후 모든 화면에 같은 자로 대는 규칙)

1. **화면당 하나의 주 행동.** 홈 = "마음을 고른다". 나머지는 전부 보조.
2. **색은 3+1+1.** 종이 · 먹 · 소나무(주 행동) · 점토(도장·기도) · 골드(이루었다 전용).
   강조가 두 번 쓰지면 강조가 아니다.
3. **그림(아이콘)은 구조, 이모지는 내용.** 탭·버튼·제목에는 24px SVG 선 아이콘,
   기분·날씨·계절처럼 '그 자체가 내용'인 자리에만 이모지를 남긴다.
4. **글자는 최소 13px급, 본문 줄높이 1.6, 한글 자간 -.011em.** 영문 장식 라벨은 폐지.
5. **움직임은 정보 전달용.** 라우터가 화면이 바뀌었다고 표시한 때에만 진입 애니메이션,
   누름 피드백(1px)과 포커스 링. `prefers-reduced-motion` 전면 존중.
6. **상태를 색만으로 알리지 않는다.** 선택 = 표시줄+굵기+채움, 방문 = 도장+체크 아이콘.
7. **상업은 흐름의 끝에.** 상점·플러스·광고는 첫 화면 하단 한 장, 잠금은 "열 수 있다"는 사실만.

## 3. 바꾼 것 (구현 요약)

### 3-1. 셸 · 내비게이션
- `index.html`에 **24px SVG 아이콘 스프라이트**(`<symbol id="i-…">` 38종) 인라인.
  앱 JS의 `ic(name)`이 `<use>`로 참조 → 이모지·`grayscale` 필터 제거.
- 하단 탭: 선택 상태를 **위 표시줄 + 굵기 + 아이콘 stroke 두께**로. `aria-current="page"`를 라우터가 부여.
- 상단 바: `플러스` 칩을 그라디언트 금색에서 '골드 테두리 칩'으로 낮춤(구독 상태일 때만 채움).
  `본문으로 바로가기` 클래스 불일치 수정(`.skip-link`), `theme-color`를 `#f6f1e7`로 통일(manifest·SEO와 동일).
- 스크롤 시에만 topbar 경계(선·그림자)가 생긴다. 첫 화면을 무겁게하던 상시 그림자 제거.
- 서비스워커 `CACHE_NAME` → `maeumjeongwon-v3`, `features.js`도 버전 태그로 통일(스플릿트캐시 무효화).

### 3-2. 타이포 · 토큰 (⑮ 디자인 시스템 v3)
- `--font-ui` / `--font-display` 토큰. 로드하지 않는 웹폰트 이름은 앞세우지 않고,
  세리프가 없는 환경은 본 문체로 조용히 대체된다하도록 폴백 체인을 명시. SVG `<text>`는 변수를 못 읽으므로
  `DISPLAY_FONT` 상수로 동일 스택을 공유(108 염주 중앙 숫자).
- 자간 `-.011em`, 본문 줄높이 1.6, 마찰 최소: `.section-label`/`.eyebrow` 폐지 → `section-kicker`(한국어·13px급).
- 스케일 토큰: 여백 `--s1…--s6`, 모서리 `--r-sm/--r/--r-lg`, 그림자 2종, 포커스 링 `--ring`,
  이징·지속 `--ease/--dur-1..3`. 카드 안 카드는 배경 1단계(`--paper`)로만 구분.

### 3-3. 정보 구조 (홈)
`오늘 인사 → 마음 처방전(주 행동) → 매일의 리추얼 → 내 순례(결과) → 지금 가기 좋은 곳(가로 레일)
→ 여행 계획 → 쉬는 도구 → 읽을거리·상점 → 면책`
- 처방전은 선택과 결과를 한 카드에서: 기분 칩 → 처방 문장 → 사찰 한 줄 → `이야기 읽기`/`계획에 담기`.
- 등급·염주는 '내 순례' 한 장으로 압축(진행 바 + 미터 3개 + 다음 미션 한 줄). 다크 히어로 카드·장식 오브 제거.
- 계절 추천 + 많이 찾는 사찰은 **가로 스냅 레일**로 합쳐 세로 스크롤 3~4장 분량을 아낀다.
- 스토리·상점·플러스는 리스트 한 장(`읽을거리 · 내려받기`)으로. 홈 안의 광고 자리 없음.

### 3-4. 사찰 상세 = 행동 화면
- 하단 **고정 행동판**(sticky): `방문 인증`(주) · `길찾기`(보조). 모바일에서는 항상 손끝에,
  ≥1120px에서는 일반 버튼 줄로 풀린다(마크업 한 벌, CSS 두 벌).
- 그 외 7개 도구는 카드 안 리스트(`오디오 도슨트·AI 안내·수첩·계획에 담기·지도·스토리·오프라인`)로 위계화.
- 데모 체크인은 주 행동 옆에서 리스트 아래로 이동(테스트 수단이 정식 경로처럼 보인 문제).
- 확인 필요 항목은 경고 톤 카드(`.verify-card`)로, 출처·면책은 그대로 하단에.

### 3-5. 컴포넌트
- 버튼 3단계(`.btn` / `.ghost`·`.soft` / `.text`) + `.btn-group`(좁은 화면 자동 나눔),
  누름 피드백·포커스 링·`:disabled` 기준 충족(`min-height:48px`).
- 목록 행 `.titem`: 도장(印)은 원형 배지 → 각진 인장, 방문은 채운 인장 + 체크 태그, 행 끝에 화살표.
- 탐색 4단 탭은 크롤 칩 → **세그먼트 컨트롤(.seg)**. 전통사찰 검색은 흩어진 입력 3개 → `.searchbar` 한 덩어리.
- 시트 모달: 상단 그랩 핸들 + 항상 보이는 닫기 버튼(JS가 시트에 주입), 배경 스크롤 잠금 유지.
- 토스트: 먹빛 → 소나무 짙은 색, `prefers-reduced-motion`에서 멈춤.
- 잠금(`.locked`)·보상형 광고 안내는 예측 가능한 두 선택지로 나란히, 자물쇠 이모지는 아이콘으로.
- 빈 상태(`.empty`)·스켈레톤(`.skel`, 부트 화면·지연 데이터) 신설 — 기록 0개인 첫 사용자에게 다음 행동을 준다.
- `완료` 태그·진행률은 골드 1색, 위험(확인 필요)은 danger 톤. 색+아이콘+문자로 상태 표현.

## 5. 두 번째 라운드 — 5절에 미뤄 둔 것 4가지

순서를 지켰다. **시맨틱 토큰 → 저조도 모드 → 홈 순서 개인화 → 탐색 검색 상시화.**
앞의 것이 뒤의 것의 전제였기 때문이다(색 이름이 정리되지 않은 상태에서 다크를 얹으면
컴포넌트를 전부 다시 열어야 한다).

### 5-1. 시맨틱 토큰 — 색을 두 겹으로 쪼갰다 (`css/style.css` ⑮-1)

```
① 팔레트   --paper / --ink / --pine / --clay / --gold …   색값 그 자체. '어디에 쓰는지' 모른다.
② 시맨틱   --surface-0..3 · --surface-sunken               면의 깊이
           --text-1/2/3                                   글자의 위계
           --border-1/2                                   선의 위계
```

- **컴포넌트는 ①을 부르지 않는다.** 전부 ②로 갈아탔다(레거시 레이어 포함, 파일 전체 0건).
  `server/test/design-system.test.js` 2번이 이를 지킨다 — 새로 색을 넣을 때
  `var(--card)`라고 쓰면 그 자리에서 실패한다.
- 옛 이름(`--accent`, `--accent2`, `--bg`)은 ②에서 팔레트를 가리키게만 두어,
  레거시 규칙도 테마를 따라오게 했다.
- `rgba()`가 필요한 자리는 숫자 토큰을 함께 둔다(`--shade`, `--scrim`, `--pine-rgb`,
  `--paper-rgb`, `--card-rgb`, `--clay-rgb`, `--glow-rgb`). 색 하나를 `--shade`로 끌어올리니
  그림자·스크림이 테마와 같이 움직인다.
- **강조색 위의 글자를 토큰으로 분리**(`--on-pine` / `--on-clay` / `--on-gold` / `--on-deep`).
  이게 없으면 다크 모드에서 버튼이 무조건 깨진다(아래 5-2).

### 5-2. 저조도(다크) 모드 — 팔레트 ①만 갈아 끼운다 (⑮-1d · ⑮-1e)

`:root[data-theme=dark]` 하나에 **팔레트만** 다시 적었다. 컴포넌트 규칙은 한 줄도 손대지 않았다.

- 왜 `prefers-color-scheme` 미디어쿼리가 아닌가: 앱 안에서 하루 중에도 바꿔야 하기 때문이다.
  새벽예불・야간 산행에서만 어두운 화면이 필요한데, OS 설정을 바꾸게 할 수는 없다.
  → `<html data-theme>` 하나로 확정하고, 값은 `localStorage('maeumjeongwon.theme.v1')`에 둔다.
  **직접 고른 적이 없으면** OS 설정 변화를 따라간다.
- **FOUC**: `index.html`의 `<head>` 인라인 스크립트가 첫 페인트 전에 `data-theme`를 정한다.
  앱 상태(`maeumjeongwon.v1`)를 기다릴 수 없어서 테마 값만 별도 키로 뺐다.
- 대비는 Material 3 방식을 택했다: 어두운 화면에서 강조색은 **밝히고**, 그 위의 글자는
  **어둡게 뒤집는다**(`--on-pine:#0e1511`). 흰 글자를 고집하면 `#5f9a78` 위에서 3.3:1로 깨진다.
  주요 조합을 계산해 AA(4.5:1)를 확인했다 — 본문 14.2:1 · 보조 6.8:1 · 주 버튼 5.6:1 ·
  소나무 링크 4.9:1 · 점토 6.1:1 · 골드 8.4:1 · 위험 6.2:1.
- 완전한 검정 대신 **먹빛이 감도는 어둠**(`#121815`) — 한지 앱이던 색온도를 유지한다.
  어두운 화면에서 그림자는 경계를 만들지 못하므로 면은 선으로 가른다(그림자 토큰도 약하게 교체).
- 예외는 ⑮-1e 한 블록에 모았다: 도감 '아직' 칸의 `filter:brightness(0)`(어두운 화면에서는
  반대로 지워짐), leaflet의 하얀 팝업·컨트롤, 지도 타일 감광(`brightness(.72)`).

### 5-3. 홈 순서 개인화 — '내가 남긴 기록' 3건 (js/app.js `viewHome`)

| 사용자 | 1등 카드 | 이유 |
|---|---|---|
| 처음 | 마음 처방전 | 이 앱이 시키는 일은 하나 — 마음을 고르는 것 |
| 기록 3건 이상 | 내 순례 | 이미 걷는 사람은 "어디까지 왔고, 다음이 무엇인지"가 먼저 읽혀야 오늘의 한 걸음이 정해진다 |

- **카드 내용·생김새는 그대로 두고 순서만 바꿨다.** 순서가 효력이 있는지, 내용이 효력이 있는지
  갈라 보려면 한 번에 하나만 움직여야 한다. (A/B 분배는 아직 붙이지 않았다 — 붙일 때
  `data-home-order` 속성이 이미 붙어 있어 지표만 연결하면 된다.)
- 첫 실행에는 데모 표본을 자동으로 넣지 않는다. `SAMPLE_DATA`는 사용자가 `샘플 값 채우기`를 눌렀을 때만 표시하며,
  각 행에 `sample: true`를 붙여 실제 GPS 방문·수첩 기록과 구별한다. 홈 순서 개인화는 사용자가 직접 남긴 기록만 센다.

### 5-4. 탐색 검색 상시화 (js/app.js `viewExplore` · `bindExplore`)

- 검색칸을 **탭(순위별·테마별·지역별·전통사찰) 위**로 올리고, 상단바 바로 아래에 붙잡아 두었다
  (`.explore-search`, sticky). 991곳을 훑는 동안 위로 올라갈 필요가 없다.
- 네 탭이 모두 같은 검색어로 걸러진다. 전통사찰 탭에만 있던 별도 입력(`#tq`)은 정리했다.
- **못 찾았을 때 '끝'이라고 말하지 않는다** — "수록 사찰에서 못 찾았어요 → 전통사찰 991곳에서 찾기"
  한 줄로 넘어가는 길을 준다.
- 주소 규칙: `#/explore/<탭>[/<탭의 선택값>]/<검색어>`. 입력마다 `history.replaceState`로
  주소만 갱신한다 — `pushState`면 '뒤로' 한 번에 글자 하나씩 되돌아간다.
  결과 칸(`#eres`)만 다시 그리므로 커서도 튀지 않는다.

## 7. 현장 중심 리프레시 — 브랜드 · 방문 정보 · 여정 (2026-10-16)

- 서비스 표기를 **절로가 — 마음 따라 걷는 사찰 순례**로 통일했다. 헤더·PWA 설치명·메타데이터·정적 SEO·완주증·도슨트 안내도 같은 이름을 쓴다.
- 첫 실행은 빈 기록으로 시작한다. 가짜 GPS 방문·수첩을 자동 생성하지 않고, 사용자가 원할 때만 예시 데이터를 채운다. 마음 추천을 먼저 보여 준 뒤 선택 온보딩과 분석 동의를 제시한다.
- 마음 추천 카드에 추천 기준(고른 마음 + 사찰 테마)을 표시해 추천이 진단이나 효험 판정이 아니라는 점을 분명히 했다.
- 사찰 상세는 주소·개방시간·입장료·주차·대중교통을 상단의 **방문 준비** 카드로 모으고, 변경 가능·확인 필요 상태를 명시한다. `도착 후 방문 인증`과 `길찾기`를 정보 바로 아래에 고정 행동판으로 배치했다.
- 순례 화면에 GPS 방문과 수첩을 잇는 **걸어온 여정** 타임라인 및 빈 상태를 추가했다. 예시 기록은 `예시`로 표시한다.
- 지도에 지도/목록 전환과 필터 연동 목록을 추가하고, 전국 축척에서는 가까운 사찰 마커를 화면 좌표 기반으로 군집화한다. 확대하면 개별 마커로 돌아간다.
