# 사경첩(寫經帖) — 주사 한 색 디자인 적용 (2026-11)

> 요청받은 시안(단일 주사색 · 사경첩 격자 · 붓글씨 스트리밍 · 인장 CTA · 복원력 있는 부팅/가입 · 적응형 리포트)을
> **문서가 아니라 화면으로** 옮긴 라운드. 무엇을 왜 그렇게 바꿨고, 무엇을 바꾸지 않았는지 남긴다.
> 가드: `server/test/design-sagyeong.test.js` (10개) · 기존 `design-system` · `mobile-ux` 가드가 그대로 함께 돈다.

## 1. 진단 — 기존 화면과 시안의 거리

| 시안 | 적용 전 상태 | 이번 라운드 |
|---|---|---|
| 배경 한지 · 글 먹 · 강조 **주사 하나** | 종이 `#f6f1e7`, 강조 소나무(초록)+점토+골드 3색 | 종이 `#FAF7F2`, 글 `#1A1A1A`, 강조 `#B71C1C` **하나** (점토는 도장, 먹금은 '이루었다'에만) |
| 사경첩 격자 위의 상담 | 카드 더미를 아래로 쌓는 모달 | `#/` 상담 시트 = **격자 위의 첩**. 질문 하나가 '한 장(第 一 問)' |
| AI 답은 붓글씨처럼 **스트리밍** | 응답이 한 번에 `innerHTML` 로 교체 | 한 글자씩 앉고, 붓끝 커서가 깜빡인 뒤 구절·실천·사찰이 순서대로 |
| **인장** 모양 전송 CTA(엄지 존) | 시트 가운데의 넓은 파란/초록 버튼 | 72px 붉은 도장 `問` — 시트 하단 고정(`position:sticky` + `--safe-b`) |
| 가입은 **이메일 + 비밀번호 2칸** | 이메일 · 닉네임 · 비밀번호 · 비밀번호 확인 4칸 | 2칸 + '보기' 토글. 닉네임은 서버가 이메일 앞부분으로 만든다 |
| 부팅/가입 실패 시 **복원력 있는 화면** | 깨지면 빈 화면, 복구 수단 없음 | `#boot` 인라인 카드(정상 부팅에는 숨김 — **6초 뒤 실패했을 때만**) + 네트워크 점검 + **새로고침 / 캐시 초기화 / 게스트로 보기** |
| 리포트는 **쌓인 만큼만** 말한다 | 방문·수첩 통계만 (상담 기록 없음) | `#/report` 에 **마음 사경** 블록: 1~2장 격려 카드 / 3장부터 꺾은선·낱말·PDF |

기존 기능은 그대로다. 사찰·순례·수첩·플래너 리포트는 손대지 않았고, 리포트 화면 **위에** 상담 블록을 얹었다.

## 2. 색 — 왜 '하나'로 줄였나

```
낮                                  저조도
--paper  #FAF7F2  한지             --paper  #14100F  먹빛
--ink    #1A1A1A  먹               --ink    #F2EDE7
--pine   #B71C1C  주사(주 행동)     --pine   #E2584A  (밝히고, 그 위 글자는 어둡게 뒤집음)
--clay   #8E3B2C  도장(印)·기도      --clay   #D98B72
--gold   #6B4E2E  먹금(완성)         --gold   #D9BC8C
```

- 강조가 셋이면 어디를 먼저 봐야 할지 매번 다시 판단하게 된다. **주사 하나**만 '지금 할 일'에 쓰고,
  점토(도장·기도)와 먹금(완성)은 **의미가 붙은 자리에만** 남겼다.
- 색을 바꾼 곳은 `css/style.css` ① 팔레트 두 블록과 파생값(rgba 숫자)뿐이다. 컴포넌트는 ② 시맨틱 토큰만 부르므로
  화면 규칙은 한 줄도 열지 않았다 (`design-system` 1·2·3번 가드가 계속 지킨다).
- 대비(측정값, WCAG AA 4.5:1): `#B71C1C` on `#FAF7F2` **6.47:1**, 인장 위 글자 `#FFFDF9` on `#B71C1C` **6.47:1**.
  저조도 주사 `#E2584A` on 카드 **4.75:1**. `mobile-ux` 14번 가드가 낮/저조도 17쌍을 매번 다시 계산한다.
- 함께 움직인 표기: `manifest.theme_color`·`background_color`, `index.html`·`tools/build-seo.js` 의 `theme-color`,
  `js/app.js` 의 `THEME_BAR`. (PWA 상태바가 앱 배경과 다른 색으로 튀지 않게)

## 3. 사경첩 격자 (SCR-MAIN-001)

- **모눈은 배경에만.** 32px 칸의 가는 선(9%)과 네 칸마다 조금 진한 선(16%)을 `repeating` 이 아니라
  `background-image` 4겹 + `background-size` 로 깐다. 글자 위에 겹치는 의사요소를 두지 않는다 — 판독성이 먼저다.
- **접힌 첩의 실밥.** `.sagye-paper::before` 가 왼쪽에 점선 실밥을 그린다. '넘겨 읽는 책'이라는 인상은
  카드 모서리를 둥글리는 것보다 이 한 줄에서 온다.
- **한 장 = 한 질문.** `第 一 問` / 날짜 / 질문(세리프, 왼쪽 주사 괘선) / 답. 질문이 쌓이면 위로 남는다.
  상담은 한 번에 끝나지 않고, 앞장이 보여야 '결'이 보이기 때문이다.
- **붓글씨 타이핑.** `typeInto()` 가 20ms 간격으로 글자를 앉히고, 마지막 글자 뒤에서 붓끝(`.sagye-typing::after`)이 깜빡인다.
  글자 수가 많아도 2초 안쪽이 되도록 한 번에 넣는 글자 수를 길이에 맞춰 계산한다.
  `prefers-reduced-motion: reduce` 이면 **즉시 완성**하고 커서도 멈춘다. 스크린리더는 `aria-busy` 로 기다렸다가
  완성된 문장을 한 번에 읽는다(글자마다 읽지 않게).
- **인장(인장 CTA).** 72px 붉은 사각 도장, 글자는 종이색(파낸 자국), `aria-label="상담 보내기"`.
  `.sagye-foot` 가 `position:sticky; bottom:0` 으로 시트 하단에 붙어 **엄지 존**을 지키고 `--safe-b` 로 홈 인디케이터를 피한다.
- **입력.** 내용만큼 자라는 `<textarea>`(최대 38vh) + Clear(×) + 데스크톱 `Enter` 전송(모바일은 줄바꿈 우선).
- **기록.** 답이 완성되면 질문·기분·낱말·마음 온도를 `MJ_COUNSEL.add()` 로 **이 기기에만** 남긴다(최대 60장).
  서버로 보내지 않는다 — 가드가 `addCounsel` 안에 `api()`/`fetch()` 가 없는지 검사한다.

## 4. 부팅·가입 (SCR-AUTH-001)

### 4-1 부트 카드 — 정상 부팅에는 아무것도 보이지 않는다 (2026-11 수정)
`index.html` 의 `<style>` 블록은 **일부러 `css/style.css` 를 부르지 않는다.** 색값을 한 번 더 적는 중복이
목적이다 — 배포된 CSS 가 깨져도 복구 버튼은 제자리에 있어야 한다.

처음에는 이 자리에 **전체 화면 로딩 스플래시**(도장 印 + "잠시 정원의 문을 정돈하고 있습니다" + 스켈레톤 3칸 +
큰 버튼 3개)를 두었다. 실기기에서 이 화면이 몇 초씩 붙잡고 있어서 **없앴다**:

- `#boot` 는 `hidden` 으로 시작한다. **정상 부팅에서는 한 프레임도 보이지 않는다.**
- 첫 화면을 그리지 못한 채 **6초**가 지나면 그때 카드가 열린다 — 로딩이 아니라 **실패 화면**이다.
  문구도 "화면을 열지 못했어요 / 한지가 젖어 붓이 멈춘 것 같아요"로 바꿨다(기다리라는 말을 하지 않는다).
- 카드에는 세 가지 문만 둔다: **새로고침** · **캐시 초기화**(서비스워커·캐시만 지운다. `localStorage` 의
  순례 기록은 건드리지 않는다) · **게스트로 보기**(로그인 벽 없이 둘러보기).
- 네트워크가 끊겨 있으면 카드 안에 "네트워크가 끊겨 있어요. 저장해 둔 사찰 정보는 오프라인에서도 열려요."
- 앱이 화면을 그리면 `render()` 가 `MJ_BOOT.hide()` 로 노드를 아예 지운다(페이드 없음).
- 그 사이의 '준비 중'은 본문 안의 가벼운 스켈레톤(`.boot-splash`, "절로가를 열고 있어요…")이 맡는다 —
  전체 화면을 덮지 않으므로 상단 바·탭은 처음부터 만질 수 있다.

### 4-2 가입은 두 칸
- 이메일 + 비밀번호(+ 동의 체크). 확인 칸 대신 **'보기'** 토글(`.pw-toggle`)을 둔다 — 오타로 잠기는 일은 화면에서 줄인다.
- 서버 `validateSignup` 은 닉네임을 **선택**으로 받는다. 비어 있으면 `nicknameSeed()` 가 이메일 앞부분에서
  2~10자를 만들고(한글·영문·숫자·밑줄만), 겹치면 `freeNickname()` 이 숫자를 붙인다. 직접 적었으면 예전 검증 그대로.
- 게시판의 가입 화면(`js/app/community.js`)도 같은 규칙이다(닉네임은 '선택').

## 5. 리포트 — 쌓인 만큼만 (SCR-REP-001)

`#/report` 는 원래 **순례(방문·수첩) 리포트**다. 시안의 상태1/상태2 는 '상담 기록' 기준이라 데이터가 없었다.
그래서 화면을 갈아엎지 않고, **상담 기록만으로 계산되는 블록을 리포트 맨 위에** 얹었다.

| 기록 | 화면 |
|---|---|
| 0장 | "아직 사경을 펼치지 않았어요" + 마음 사경 열기 |
| 1~2장 | **격려 한 장** — 숫자 대신 문장. 마지막 장의 낱말만 곁들인다 |
| 3장~ | **마음의 결**: 최근 8장의 마음 온도(1~5)를 주사 그라데이션 꺾은선으로, 되풀이되는 낱말을 `#불안 3회` 격자로, 맨 아래 **PDF로 저장·인쇄** |

- 기준을 3장으로 둔 이유: 한 장은 우연이고, 세 장이 쌓이면 결이 보인다. 두 장에서 통계를 말하면 거짓말이 된다.
- 마음 온도는 기분 라벨(6종) + 낱말(불안·지침·외로움·화 −0.3 / 감사·기도·쉼 +0.3)로 계산해 1~5 로 자른다.
- 그래프 좌표는 `trendPoints()` 라는 순수 함수 — 화면 없이도 검산할 수 있다.
- 상담 기록은 기기 안에만 있으므로 리포트에 "기기를 바꾸면 따라가지 않아요"를 함께 적었다.

## 6. 첫 화면 예산 — 138.9KB / 140KB

색과 격자를 넣자 첫 화면이 **142.8KB** 로 예산을 2.8KB 넘었다. 예산을 올리는 대신 **필요한 화면에서만 받게** 옮겼다.

- `css/sagye.css` (격자·붓글씨·인장·리포트 조각) + `js/app/report.js` (마음 사경 리포트) = 지연 자산 `sagye`
- `#/report` 는 `NEEDS.report = ['sagye']` 로 먼저 받고(라우터가 기다린다), 상담 시트는 `features.js` 가 열기 전에
  `MJ_LOADER.ensure(['sagye'])` 로 요청만 걸어 둔다(기다리지 않는다 — 도착하면 칠해진다).
- 지연 모듈이 없을 때를 대비해 `counselSection()` 은 "불러오지 못했어요 + 새로고침" 카드를 낸다.
- 남은 몫은 문장·주석을 다듬어 회수했다: 142.8 → **138.9KB** (`npm run budget`).
  부트 카드의 인라인 CSS/JS 는 예산에 잡히지만 **지우지 않는다** — 깨진 배포에서 유일한 복구 경로다.
  (로딩 스플래시를 없애면서 도장·스켈레톤·힌트 규칙이 빠져 인라인 CSS 는 오히려 줄었다.)

### 실기기에서 아직 확인해야 하는 것
- [ ] iOS Safari: 시트 하단 인장이 홈 인디케이터와 겹치지 않는가(`--safe-b`), 키보드가 올라올 때 인장이 가려지지 않는가
- [ ] Android Chrome: 격자 선이 저해상도에서 흐릿하게 뭉개지지 않는가(32px 칸 · 1px 선)
- [ ] 저조도: 주사 `#E2584A` 위 글자가 실제로 읽히는가(계산값 4.75:1 — 경계선)
- [ ] 손떨림/큰 글씨 모드에서 인장 72px · 격자 26px(≤380px) 가 답답하지 않은가
- [ ] 붓글씨 타이핑이 긴 답(600자↑)에서 3초를 넘기지 않는가
- [ ] `캐시 초기화` 가 순례 기록을 지우지 않는가 (실기기 브라우저별 확인)
