# 모바일 조작 규칙 적용 — 손끝 48dp · 입력 · 옵션 · 피드백 (2026-11)

"모바일 앱 디자인 최적화 가이드"를 **이 앱의 화면에 실제로 대 보는** 작업이다.
가이드는 원칙을 말하고, 이 문서는 **어느 파일 몇 번째 규칙이 그 원칙을 지고 있는지**를 적는다.
원칙을 새로 만드는 대신 이미 있는 것과 비어 있는 것을 갈라서, 비어 있는 자리만 채웠다.

---

## 1. 진단 — 가이드 15항목 × 이 앱

| 가이드 | 이 앱의 상태 (2026-10 기준) | 이번 라운드 |
|---|---|---|
| 터치 타겟 48×48dp | `--tap:44px`. 버튼은 44, 칩은 36, `.btn.small` 은 38 — 셋 다 48 아래 | **48px** 로 올리고, 상단 칩만 44px + 히트 슬롭 4px |
| 엄지 존(하단)의 주 행동 | 하단 탭바 + 사찰 상세 하단 고정 행동판(`.actionbar`) 이미 있음 | 그대로. 대신 **행동판이 48px·안전영역을 지키는지** 가드로 묶음 |
| 세로 레이아웃 중심 | 1열 세로 스크롤 + 가로 스냅 레일(발견 영역) | 그대로 |
| 한 화면에 하나의 행동 | 홈 = 마음 고르기, 상세 = 방문 인증 (2026-10 리프레시) | 그대로 |
| 시각적 계층 | 크기·대비·여백 토큰 + `.section-kicker` | 그대로. **골드 배지 대비(4.40:1)만 고침** |

| 수량은 스텝퍼 | 수량 입력 자체가 없었음 (여행 계획에 인원 항목 없음) | **`.stepper` 신설 + '함께 가는 사람(1~20명)'** |
| 5개 이하면 직접 노출 | 수첩 날씨(5) · 여행 기간(5) · 이동 수단(4) · 글 종류(3) 이 **전부 드롭다운** | `.choices` 로 펼침. 7개(동행 스타일)만 드롭다운 유지 |
| 무거운 모달 대신 시트 | 하단 시트 + 넓은 화면 중앙 대화상자 ✓ | 그대로. 닫기 버튼을 48px 로 |
| 로딩·피드백 | 스켈레톤·빈 상태·토스트 ✓ / 제출 중 상태는 **버튼이 잠기기만** 함 | `aria-busy` + 스피너, 행·카드 누름 피드백 |
| 경량·지연 로딩 | 로더 표 + 140KB 예산 | 예산이 **1.5KB 초과** → 추천 엔진을 지연 자산으로 (6절) |

## 2. 손끝 — 보이는 크기와 닿는 크기를 나눈다

```
--tap:48px      1차 행동: .btn · 목록 행 · 입력 · 선택 칩 · 스텝퍼 · 시트 닫기
--tap-sm:44px   상단 크롬(칩): 보이는 높이 44px
.chip::after{inset:-2px -3px}   → 위아래 2px 씩 넓혀 실제 히트 영역 48px
```

- 칩 사이 간격이 6px 이라 히트 영역은 **이웃 칩을 잡아먹지 않는다**. 밀도(상단바 높이)와
  손끝(48px)을 동시에 만족시키는 유일한 방법이라 이렇게 나눴다.
- `.btn.small` 은 글자를 줄이고 **높이는 48px 로 통일**했다. '작은 버튼'은 정보량이 적은
  버튼이지 손끝이 작은 버튼이 아니다.
- 320~380px 구간에서 칩 높이를 34px 로 낮추던 규칙을 **삭제**했다. 자리를 아끼려고 손끝을
  잃는 교환은 이 앱(4060 사용자)에서는 손해다. 대신 글자·좌우 여백만 줄인다(⑯-7).
- `input[type=file]`, `select` 도 같은 48px. iOS 자동 확대 방지(`font-size:max(16px,1em)`)는 유지.

## 3. 입력 — Clear(×) 는 마크업이 아니라 규칙

템플릿이 60여 곳이라 손으로 넣으면 반드시 빠진다. 그래서 **그린 뒤에 한 번 감싼다**.

```
render()   → $view.innerHTML = html; enhanceFields($view);
openModal()→ m.innerHTML = html;    enhanceFields(m);
```

- 값이 있을 때만 보이고(`hidden`), 누르면 값 → `input`/`change` 이벤트 → 포커스까지 되돌린다.
  검색은 `input` 을 듣고 결과를 다시 그리므로 **지우면 결과도 즉시 돌아온다**(실DOM 확인).
- 제외: `password`(지우는 것이 곧 노출 안내), `date`·`file`(브라우저 자체 UI).
- 탐색 화면의 '지우기' 칩(`#eclear`)은 **없앴다** — 같은 일을 하는 버튼 두 개를 두지 않는다.

## 4. 옵션 — 5개는 펼치고, 7개는 접는다

```
.choiceGroup(name, label, opts, cur)   →  <div class="choices"> + hidden input(name)
```

| 화면 | 항목 | 개수 | UI |
|---|---|---|---|
| 수첩 | 날씨 | 5 | 펼침 (`.choices`) |
| 여행 계획 | 기간 | 5 | 펼침 |
| 여행 계획 | 이동 수단 | 4 | 펼침 |
| 게시판 | 글 종류 | 3 | 펼침 |
| 여행 계획 | 동행 스타일 | 7 | **드롭다운 유지** |
| 탐색·계획 | 시·도 17 · 테마 9 · 사찰 1,000+ | 9+ | 드롭다운 |

- 폼 값은 `hidden input` 이 들고 있어 **기존 `FormData`·`change` 처리(초안 저장, 이동 수단별
  시간 재계산, 추천 조건)가 한 줄도 바뀌지 않았다.** 클릭 처리는 셸의 위임 한 곳에서 하므로
  계획·게시판 모듈도 같은 규칙을 자동으로 따른다.
- 선택 상태는 색 하나로 알리지 않는다: **체크 아이콘 + 테두리 + 굵기 + `aria-pressed`**.

## 5. 수량은 스텝퍼 · 상태는 즉시

- `.stepper` 신설. 여행 계획의 **'함께 가는 사람(1~20명)'** 이 첫 사용처다. 경계에서 −/+ 가
  잠기고, 값은 `<output aria-live="polite">` 로 읽히며, 저장된 계획 상세에는 `· 3명` 으로 남는다.
  예전 계획에는 이 값이 없으므로 **있을 때만** 표시한다(마이그레이션 없음).
- 누름 피드백: 행·카드·칩은 `:active` 에서 배경·테두리가 먼저 바뀐다(움직임 최소화 사용자에게도 보인다).
- 진행 피드백: `markBusy()` 가 `disabled` + `aria-busy` + 스피너(`::before`)를 함께 켠다.
  수첩 저장(사진 축소로 실제 1초 걸림)과 로그인·가입에 적용. 두 번 눌러 두 번 저장되는 것도 막는다.

## 7. 예산 — 늘어난 만큼 다른 데서 회수

가이드를 적용하니 첫 화면 gzip 이 **141.5KB / 140KB** 로 예산을 넘었다(CSS +3.3KB, JS +1.6KB).
`docs/design-refresh.md` 6절에 미뤄 둔 숙제를 여기서 처리했다.

- **계획 추천 엔진(`js/planner-reco.js`, gzip 5.3KB)을 지연 자산으로 이동** — 계획 화면에서만
  쓰이는데 첫 화면이 늘 받고 있었다. `js/lib/loader.js` 의 `planner` 자산에 넣고(추천 엔진 →
  `planner.js` 순서), `index.html`·`sw.js` PRECACHE 에서 빼서 LAZY 로 옮겼다.
  `js/app.js` 는 계획 모듈을 만들 때 `window.PLANNER_RECO` 를 **다시 확인**한다(늦게 도착하므로).
- 결과: 첫 화면 gzip **136.4KB / 140KB** (이번 라운드 이전 136.0KB — 기능을 더했는데 +0.4KB).
- 계획 화면은 5.3KB 늘었지만 그 화면에 들어갈 때만 받는다(라우트 표 참고: `#/planner` 37.8KB).

## 9. 의도적으로 하지 않은 것

1. **명상 타이머의 3·5·10분** — 수량이지만 '고르는 값'이 아니라 **지름길 세 개**다. 스텝퍼로 바꾸면
   10분을 고르려면 다섯 번 눌러야 한다. 프리셋이 맞다.
2. **상단 칩 5개를 '더보기' 시트로 접기** — 5개는 한 줄에 들어가고, 접으면 큰 글씨 모드에서
   오히려 한 번 더 눌러야 한다. 320px 실기기 확인 후 판단한다.
3. **1440px 이상 2열 카드의 짝 맞추기** — `docs/responsive-layout.md` 의 알려진 한계 그대로.
4. **A/B·지표** — 이번 라운드는 '규칙 준수'까지다. 48px·Clear·펼친 옵션이 실제로 이탈을 줄이는지는
   `data-home-order` 처럼 속성만 붙여 두고 동의 기반 지표로 따로 본다.
